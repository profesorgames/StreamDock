# StreamDock

Портативный загрузчик для **Windows 10/11 x64**. Один `StreamDock.exe`: без
установки и отдельных зависимостей. Разработка и кросс-сборка возможны в Codex
Cloud; окончательная сборка и проверки Windows выполняются в GitHub Actions.

## Скачать и запустить

Откройте [Releases](https://github.com/profesorgames/StreamDock/releases/latest), скачайте `StreamDock.exe` и запустите.
Если релиза ещё нет: Actions → Windows portable EXE → успешный запуск →
Artifacts → StreamDock-Windows-x64. Из архива нужен только EXE.

Программа включает .NET Desktop Runtime, yt-dlp с EJS, FFmpeg/ffprobe, Deno,
Python embedded и gallery-dl с зависимостями. Первичная подготовка требует
свободного места: примерно 1,2 ГБ с EXE и распакованными компонентами, плюс место
для скачиваемых файлов. Администратор не нужен. EXE пока не подписан сертификатом
издателя; SmartScreen может показать предупреждение.

## Использование

1. Вставьте ссылку → **Найти медиа**.
2. Выберите видео и максимальное разрешение, MP3 и битрейт, либо исходный файл/галерею.
3. Нажмите **В очередь**. У каждого задания есть папка, повтор и отмена.

YouTube и большинство видеосайтов обрабатывает yt-dlp; галереи изображений —
gallery-dl; прямые HTTP(S)-файлы скачиваются встроенным клиентом. Для видео
сохраняется исходный кодек: объединённые дорожки упаковываются в MKV без потери
качества. Видео не перекодируется в MP4. MP3 создаётся FFmpeg из лучшей доступной
аудиодорожки; выбор 320 кбит/с не повышает качество исходной записи.

**Пауза очереди** останавливает запуск следующих заданий. Текущие загрузки
продолжаются; их можно отменить отдельно. После перезапуска незавершённые задания
помечаются прерванными: нажмите ↻. yt-dlp продолжает свои `.part`-файлы; прямые
файлы повторно скачиваются с начала. Галереи отображают количество объектов,
поскольку источник не всегда сообщает полное число и объём заранее.

Cookies: при необходимости укажите в настройках путь к своему `cookies.txt`
в формате Netscape. Приложение не экспортирует cookies из браузера автоматически.
Доступность конкретных сайтов и защищённых входом страниц не гарантируется:
она зависит от сайта, региона, cookies и версии встроенных загрузчиков. DRM
не обходится. Используйте доступные вам материалы с необходимым разрешением.

## Spotify

1. Откройте [Spotify Developer Dashboard](https://developer.spotify.com/dashboard).
2. Создайте приложение, добавьте свой аккаунт в список разрешённых пользователей.
3. Добавьте Redirect URI **точно**: `http://127.0.0.1:43829/callback/`.
4. Скопируйте **Client ID** в настройки StreamDock, сохраните и нажмите
   **Подключить Spotify**. Client Secret нигде не нужен.
5. Включите песню → **Найти текущий трек** → проверьте предложенные записи →
   **Сохранить выбранное в MP3**.

Требования Spotify к Developer Dashboard, Premium и доступу в development mode
могут меняться; приложение не снимает эти ограничения. Spotify отдаёт только
название, исполнителя и длительность. Поиск идёт через yt-dlp на YouTube;
сортировка учитывает исполнителя, название, длительность и версии cover/live/remix.
Совпадение может быть неточным, поэтому источник выбирает пользователь.
Токены хранятся с шифрованием Windows DPAPI текущего пользователя. Кнопка
отключения удаляет их. Интеграция Spotify в ChatGPT не передаёт сессию в EXE.

## Трей, автозапуск и данные

Крестик по умолчанию скрывает окно в трей. Двойной щелчок по значку открывает его;
**Выход** в меню трея завершает программу и останавливает дочерние процессы.
Можно отключить закрытие в трей в настройках.

Автозапуск **изначально выключен**. Включение и сохранение настроек записывает
`"полный путь\StreamDock.exe" --tray` в
`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`. Окно при входе в Windows
не открывается. После переноса EXE сохраните настройки снова. Отключение удаляет
только значение StreamDock.

Данные находятся в `%LOCALAPPDATA%\StreamDock`: настройки, история, зашифрованные
токены и проверенные по SHA256 компоненты. Загрузки по умолчанию —
`%USERPROFILE%\Downloads\StreamDock`. У каждого задания своя папка. Ничего не
устанавливается системно. Чтобы удалить программу полностью: выключите
автозапуск, выйдите из трея, удалите EXE и папку данных. Скачанные файлы сохраняются.

## Сборка

Стек: C#/.NET 10 LTS, WPF, WinForms NotifyIcon, стандартный HttpClient.
Интерфейс не требует WebView2, браузерного движка или Electron.

На Windows с .NET SDK из `global.json` и Python 3.13:

```powershell
./scripts/build.ps1
./scripts/test-windows.ps1
```

На Linux в облаке:

```bash
python3 scripts/prepare_payload.py
dotnet run --project tests/StreamDock.Tests -c Release
dotnet publish src/StreamDock.App -c Release -r win-x64 --self-contained true -o dist
```

`prepare_payload.py` использует только стандартную библиотеку. Все зависимости
зафиксированы по URL, версии и SHA256 в `scripts/dependencies.lock.json`. Внешние
компоненты не загружаются при запуске EXE. Извлечённые файлы проверяются по
хешам, повреждённые восстанавливаются из EXE. Обновление загрузчиков — через
обновлённый lock-файл и новую сборку; скрытого автообновления нет.

## GitHub Actions и проверки

`.github/workflows/windows.yml` собирает приложение на `windows-2025` при push,
PR и ручном запуске. `dist` содержит один исполняемый файл и контрольную сумму.
Затем EXE копируется **один** в путь с пробелами и кириллицей и запускается
как готовый пользовательский продукт:

- `--self-test`: проверка распаковки и версий всех инструментов, DPAPI,
  генерация локального MP4, скачивание через HTTP, получение реального MP3
  с помощью yt-dlp/FFmpeg и проверка кодека ffprobe;
- `--ui-smoke`: окно WPF, страницы, выбор качества/MP3, очередь, закрытие и
  повторное открытие; сохраняется скриншот;
- `--tray-smoke`: инициализация приложения без показа окна.

Core-тесты дополнительно проверяют отмену дерева процессов, буквальные аргументы
без shell, отмену HTTP, очередь и ограничение параллелизма, восстановление истории,
форматы загрузок, PKCE по RFC и обновление Spotify-токена на подставном сервере.
Личный Spotify-аккаунт и публичные видеосайты в CI не используются; такие
проверки требуют реального аккаунта и доступных источников.

EXE и отчёты появляются в Artifacts. Тег `v*` публикует GitHub Release после всех
проверок. Также можно запустить workflow вручную с `release=true`. У репозитория
должны быть включены Actions и разрешена запись workflow-токена для job релиза.
